# Odoo Order Sync Retry System

**Status:** ✅ Production Ready  
**Last Updated:** December 20, 2025

## Overview

This document describes the automatic retry and customer notification system for Odoo order synchronization failures. The system ensures that customers are informed within 30 minutes if their order cannot be synced to Odoo, while continuously attempting to resolve the issue.

---

## Problem Statement

In serverless environments (Vercel), Odoo sync runs inline during order creation. If Odoo is temporarily unavailable or slow, the sync can fail. Without retries:
- Orders are marked as "failed" immediately
- No automatic recovery
- Customer is unaware of the issue
- Manual intervention required

---

## Solution: 30-Minute Retry Window with Customer Notification

### Key Features

1. **Automatic Retries**: Failed syncs are retried every 5 minutes
2. **30-Minute Deadline**: Maximum 30 minutes from order creation to final resolution
3. **Customer Notification**: Apology email sent if sync fails within 30-min window
4. **Retry Tracking**: Database tracks attempts, errors, and notification status
5. **Graceful Degradation**: Orders are still saved even if Odoo sync fails

---

## Architecture

```
Order Created
     ↓
Inline Odoo Sync (Serverless)
     ↓
  Success? ──Yes──→ Order Confirmed
     ↓
     No
     ↓
Mark as "failed" + Track attempt
     ↓
Cron Job (every 5 min)
     ↓
Retry Sync (max 5 attempts)
     ↓
  Success? ──Yes──→ Order Confirmed
     ↓
     No
     ↓
Near 30-min deadline?
     ↓
     Yes
     ↓
Send Apology Email to Customer
     ↓
Continue retrying until 30 min
     ↓
After 30 min: Mark as "failed_permanent"
```

## Database Schema

### New Fields in `Order` Model

```prisma
model Order {
  // ... existing fields ...
  
  // Retry tracking
  odooSyncAttempts      Int       @default(0)
  odooSyncLastError     String?   // Last error message (max 500 chars)
  odooSyncLastAttemptAt DateTime? // When last sync was attempted
  odooSyncNotifiedAt    DateTime? // When customer was notified (null = not notified)
}
```

## Retry Logic

### Cron Job: `/api/cron/retry-odoo-sync`

**Schedule**: Every 5 minutes (Vercel Cron)

**Process**:

1. **Find Failed Orders**
   - `odooStatusSale` or `odooStatusPos` = "failed"
   - Created within last 30 minutes
   - Attempts < 5

2. **Retry Sync**
   - Call `enqueueOrderSync()` with same parameters
   - Increment `odooSyncAttempts`
   - Update `odooSyncLastAttemptAt`
   - Store error in `odooSyncLastError` if fails

3. **Check Deadline**
   - If order age >= 25 minutes (within 5 min of deadline)
   - AND customer not yet notified (`odooSyncNotifiedAt` is null)
   - Send apology email

4. **Handle Expired Orders**
   - Orders older than 30 minutes with failed status
   - Send notification if not already sent
   - Mark as `"failed_permanent"` (manual intervention needed)

### Retry Limits

- **Max Attempts**: 5 retries
- **Max Window**: 30 minutes from order creation
- **Retry Interval**: Every 5 minutes (via cron)

**Example Timeline**:
```
00:00 - Order created, sync fails (attempt 1)
00:05 - Cron retry (attempt 2)
00:10 - Cron retry (attempt 3)
00:15 - Cron retry (attempt 4)
00:20 - Cron retry (attempt 5)
00:25 - Near deadline, send email if still failing
00:30 - Deadline reached, mark as failed_permanent
```

## Customer Notification Email

### When Sent

- Order sync failing after multiple retries
- Within 5 minutes of 30-minute deadline
- OR after 30-minute deadline if not already notified
- Only sent once per order

### Email Content

**Subject**: `Order #XXXXX - Processing Update`

**Key Points**:
- Order is confirmed and saved
- Temporary technical issue
- Team will manually process
- No action needed from customer
- Sincere apology

**Tone**: Professional, reassuring, apologetic

## Environment Variables

### Required for Email Notifications

```bash
# Email SMTP Configuration (same as NextAuth)
EMAIL_SERVER_HOST=smtp.example.com
EMAIL_SERVER_PORT=587
EMAIL_SERVER_USER=your_smtp_username
EMAIL_SERVER_PASSWORD=your_smtp_password
EMAIL_FROM=noreply@yourdomain.com

# Optional: Brand name for emails
BRAND_NAME="Elite Coffee Shop"
```

### Required for Cron Security

```bash
# Vercel Cron Secret (auto-generated by Vercel)
CRON_SECRET=your-vercel-cron-secret
```

**Note**: Vercel automatically sets `CRON_SECRET` when you deploy with cron jobs configured. You can find it in Vercel Dashboard → Settings → Environment Variables.

```json

  "crons": [

      "path": "/api/sync/products",
      "schedule": "0 2 * * *"
    },
    {
      "path": "/api/cron/retry-odoo-sync",
      "schedule": "*/5 * * * *"
    }
  ]
}
```

**Retry Cron**: Runs every 5 minutes


**Permanent Failure**:
```

```

### Database Queries

**Check failed orders**:
```sql
SELECT 
  id, 
  "createdAt",
  "odooStatusSale",
  "odooSyncAttempts",
  "odooSyncLastError",
  "odooSyncNotifiedAt"
FROM "Order"
WHERE "odooStatusSale" = 'failed'
  AND "createdAt" > NOW() - INTERVAL '30 minutes'
ORDER BY "createdAt" DESC;
```

**Check notified orders**:
```sql
SELECT 
  id,
  "createdAt",
  "odooSyncNotifiedAt",
  "odooSyncAttempts"
FROM "Order"
WHERE "odooSyncNotifiedAt" IS NOT NULL
ORDER BY "odooSyncNotifiedAt" DESC
LIMIT 10;
```

## Edge Cases & Considerations

### 1. Email Service Down

**Scenario**: SMTP server unavailable when trying to send notification

**Handling**:
- Email send failure is logged but doesn't crash the cron job
- Next cron run will try again (if customer not yet notified)
- Order sync retries continue independently

### 2. Odoo Recovers Mid-Window

**Scenario**: Odoo comes back online after 15 minutes

**Handling**:
- Next cron run (at 20 min) will successfully sync
- Order status updated to "synced"
- Customer notification is NOT sent (only sent if still failing near deadline)

### 3. Multiple Concurrent Cron Runs

**Scenario**: Cron job takes longer than 5 minutes

**Handling**:
- Vercel ensures only one cron instance runs at a time
- If previous run is still executing, next run is queued
- No duplicate retries

### 4. Order Created Just Before Cron

**Scenario**: Order created at 00:04, cron runs at 00:05

**Handling**:
- First retry happens at 00:05 (1 minute after creation)
- Still have full 30-minute window
- Total retries: up to 6 attempts (initial + 5 retries)

### 5. Customer Has No Email

**Scenario**: Guest checkout without email

**Handling**:
- Notification is skipped (no email to send to)
- Order still retried normally
- Manual intervention required if sync fails

## Manual Intervention

### When Needed

- Orders marked as `"failed_permanent"`
- After 30-minute retry window expires
- Odoo still unavailable

### Process

1. **Check Order Details**:
   ```sql
   SELECT * FROM "Order" WHERE id = 'order-id';
   ```

2. **Check Error**:
   - Review `odooSyncLastError` field
   - Check Vercel logs for full error trace

3. **Manual Sync** (if Odoo is now available):
   ```bash
   # Call retry endpoint manually
   curl -X GET https://your-app.vercel.app/api/cron/retry-odoo-sync \
     -H "Authorization: Bearer $CRON_SECRET"
   ```

4. **Or Create in Odoo Manually**:
   - Log into Odoo
   - Create sale order manually
   - Update order in database:
     ```sql
     UPDATE "Order" 
     SET "odooStatusSale" = 'synced', 
         "saleOrderId" = <odoo-id>
     WHERE id = 'order-id';
     ```

## Performance Impact

### Database Load

- Cron runs every 5 minutes
- Queries only orders from last 30 minutes
- Limit 20 orders per run
- Minimal impact on database

### API Load

- Each retry makes 1 Odoo API call
- Max 20 retries per cron run (20 orders × 1 call each)
- Spread over 5-minute intervals
- Acceptable load for Odoo

### Email Load

- Max 20 emails per cron run
- Only sent once per order
- Only for orders near/past deadline
- Typical: 0-2 emails per run
